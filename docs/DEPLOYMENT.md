# Going live

The live site has three parts, each on a free plan:

| Part | Service | Address |
|---|---|---|
| Frontend (React) | GitHub Pages | `https://prem04-buzz.github.io/propconnect-ai/` |
| Backend (FastAPI) | Render web service | `https://propconnect-api.onrender.com` (Render shows the exact name) |
| Database (PostgreSQL) | Neon | a connection string Neon gives you |

GitHub Pages only serves static files, so it can't run the backend or the database. That's why there are three parts. Do the steps in this order.

## 1. Database on Neon (10 minutes)

1. Sign up at neon.com (GitHub sign-in works). Create a project named `propconnect`, region **US East**.
2. On the project dashboard, copy the **connection string**. It looks like `postgresql://user:password@ep-something.us-east-2.aws.neon.tech/neondb?sslmode=require`. Keep it private: anyone with it can read and change your data.
3. From your laptop, create the tables and load the data into Neon. In `backend/` with the virtual environment active:

   **Mac**
   ```bash
   export DATABASE_URL='paste-the-neon-string-here'
   export ADMIN_PASSWORD='a-strong-admin-password'
   alembic upgrade head
   python -m app.scripts.seed
   python -m app.scripts.load_data
   python -m app.scripts.seed_demo
   python -m app.scripts.seed_eval
   unset DATABASE_URL ADMIN_PASSWORD
   ```

   **Windows (PowerShell)**
   ```powershell
   $env:DATABASE_URL = 'paste-the-neon-string-here'
   $env:ADMIN_PASSWORD = 'a-strong-admin-password'
   alembic upgrade head
   python -m app.scripts.seed
   python -m app.scripts.load_data
   python -m app.scripts.seed_demo
   python -m app.scripts.seed_eval
   Remove-Item Env:DATABASE_URL, Env:ADMIN_PASSWORD
   ```

   You can paste the string exactly as Neon gives it; the app converts it to the right driver. The last line puts your laptop back on your local database.

## 2. Backend on Render (10 minutes)

1. Sign up at render.com with GitHub and give it access to the `propconnect-ai` repository.
2. **New → Blueprint**, pick the repository. Render reads `render.yaml` and proposes a web service called `propconnect-api`.
3. Fill in the values it asks for:
   - `DATABASE_URL`: the Neon connection string
   - `ADMIN_PASSWORD`: the same strong password you used in step 1
   - `DEMO_PASSWORD`: the password for the demo agents
   - `OPENAI_API_KEY`: your key (see "Protecting the AI budget" below)
4. Click **Apply**. The first deploy takes a few minutes. When it's live, open `https://<your-service>.onrender.com/api/health`; it should say `{"status":"ok"}`.
5. Copy that address (without `/api/health`). You need it in the next step.

`JWT_SECRET` is generated by Render automatically. `ENVIRONMENT=production` is set, so the server refuses to start if any secret is still a development default.

## 3. Frontend on GitHub Pages (5 minutes)

1. On GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. **Settings → Secrets and variables → Actions → Variables → New repository variable**: name `API_URL`, value the Render address from step 2, for example `https://propconnect-api.onrender.com`.
3. **Actions → Deploy frontend to GitHub Pages → Run workflow** (after this, it runs by itself on every merge to `main` that changes the frontend).
4. Open `https://prem04-buzz.github.io/propconnect-ai/` and sign in.

If you rename the Render service or the repository, update `API_URL` and `CORS_ORIGINS` to match.

## 4. Check that it works

- [ ] `…/api/health` returns `{"status":"ok"}`
- [ ] The Pages site loads and you can sign in as the broker and as an agent
- [ ] Refreshing a deep link such as `…/propconnect-ai/clients` still works
- [ ] The AI panel shows "AI · gpt-4o-mini" (not "Rule-based") when the key is set
- [ ] `…/docs` on the Render address opens the API documentation

## Before each user-study session

The free Render service goes to sleep after 15 minutes without visitors and takes about a minute to wake up. The login page tells people when that's happening, but it would distort a timed study.

- **Either** open the site 5 minutes before each session and sign in once,
- **or** switch the service to the **Starter** plan ($7/month) for the study weeks, then back to Free. In `render.yaml` change `plan: free` to `plan: starter`, or change it in the Render dashboard.

Create each participant's account from the **Team** page as the broker. Use anonymous names (P1, P2, …), not real ones.

## Automatic emails

When a broker assigns a client to an agent, the client gets one email introducing their agent, with the agent's address as reply-to. Each client gets at most one introduction per agent. Every attempt is recorded in the `email_log` table, and the Admin page shows it in the *Intro email* column.

Render's free plan blocks normal email (SMTP), so the app sends through Brevo's web API instead (free: 300 emails a day).

1. Sign up at brevo.com (free, no card).
2. **Senders, domains & dedicated IPs → Senders → Add a sender**: use the address emails should come from (your Gmail works). Click the link Brevo emails you to verify it.
3. **SMTP & API → API keys → Generate a new API key**. Copy it.
4. In Render → `propconnect-api` → **Environment**: set `BREVO_API_KEY` to the key and `EMAIL_FROM_ADDRESS` to the verified sender. Save; Render restarts by itself.

Without a domain of your own, some emails may land in the client's spam folder at first. A verified domain in Brevo fixes that if the product goes beyond the class project.

## Protecting the AI budget

- The OpenAI key lives only in Render's settings. It's never in the frontend or in Git.
- Each user can request at most **30 AI suggestions per hour** (`AI_REQUESTS_PER_HOUR`). Lower it if you like.
- In the OpenAI dashboard, set a **monthly budget limit** (for example $10) so a mistake can never run up a big bill.

## Updating the live site

Merge to `main` on GitHub. Render redeploys the backend and runs any new migrations; the Pages workflow republishes the frontend. Nothing else to do.

## Known limits of the free setup

- Render's free service sleeps after 15 minutes idle (see above) and has 750 free hours a month, enough for one service running all the time.
- The sign-in lockout and AI limit are kept in memory, so a restart resets them. That's fine for one server.
- Neon's free plan has 1 GB of storage per project, far more than this app needs.
